A reverse proxy lets you serve the panel and subscription on a clean domain with
automatic HTTPS, and hide the real ports behind ports 80/443. Prefer to let the
panel terminate TLS directly? Get a certificate with the
[`x-ui` SSL menu](/docs/config/ssl-certificates) instead.

## Built-in reverse proxy

This fork ships its own reverse proxy, so the common case needs no Nginx or
Caddy at all. Turn it on under **Settings → Reverse proxy**. It is a single local
TLS listener that routes by path:

| Request path | Goes to |
| --- | --- |
| Your panel's web base path | The panel |
| Your subscription path, and the JSON and Clash subscription paths while those are on | The subscription server |
| Everything else | A decoy site |

The point is the third row. Pair it with REALITY: set a REALITY inbound's
fallback `target` to `127.0.0.1:<reverse proxy port>`, and anyone who probes your
`:443` without a valid REALITY key is handed an ordinary-looking website
instead of something that reveals a panel is running here.

<Callout type="warn">
  REALITY's fallback is a blind byte relay — Xray cannot decrypt it, so the
  reverse proxy has to terminate real TLS itself. Choose **Manual** to reuse the
  panel's own certificate files, or **Automatic** to have the panel obtain one
  from Let's Encrypt. Automatic uses the HTTP-01 challenge, because Xray owns
  port 443; port 80 must be free and reachable from the internet.
</Callout>

The decoy can be one of the pages built into the panel, a static site you
upload as a zip (an `index.html` at its root or inside a single folder, up to
64 MiB), or a reverse proxy to a site you already host elsewhere.

<Callout type="info">
  If a misconfigured reverse proxy ever locks you out of the panel, turn it off
  over SSH with `x-ui setting -disableFrontProxy` and restart the panel. The
  command writes straight to the database and does not need a running panel.
</Callout>

Reach for Nginx or Caddy instead when you need things the reverse proxy
deliberately does not do: routing for services other than this panel, CDN
fronting, or per-path rate limiting and access rules.

## Closing ports

Once an inbound is reachable through a path on 443, its own public port is one
more thing for a scanner to find. **Settings → Reverse proxy → Closed ports**
lists the ports of the panel, the subscription server and your enabled inbounds
(TCP and UDP), marks the ones that are also reachable on 443, and closes the
ones you tick in the host firewall. A closed port drops what other hosts begin
towards it, including a connection they already have; the host's own traffic,
loopback and the `awg*`/`wg*` interfaces are never affected.

Closing a port you reach the panel on would lock you out, so a change that
closes a port that was open waits for your confirmation:

1. **Preview** shows what would be closed and opened, the ports that are
   refused, and the nft rules, and changes nothing.
2. **Apply** puts the rules in. A banner counts down 2 minutes.
3. Open the panel by a route that is still open (the reverse proxy on 443, or a
   VPN) and press **Confirm**. If you cannot, do nothing: the change is rolled
   back by itself. Opening ports never needs a confirmation.

The SSH ports (read from `sshd_config` and the files it includes, and any port
where sshd answers) and `443/tcp` cannot be closed. If a closed port ever cuts
you off, run `x-ui setting -openClosedPorts` as root over SSH: it forgets the
closed ports and removes the rules without needing the panel.

<Callout type="info">
  The rules live in the kernel, which forgets them at a reboot. The panel puts
  them back when it starts, so a closed port is open for the few seconds between
  boot and the panel starting. After a downgrade to a build without this feature
  the rules stay until the next reboot, or until `nft delete table inet
  x_ui_portguard`. The uninstall script removes them. A connection the host
  itself starts from a closed port still gets its replies, and closing the panel
  port of a node cuts the master's access to it.
</Callout>

## Nginx + certificate

With Nginx, obtain a certificate with `certbot` (or `acme.sh`) and reference it
in the server block:

```bash title="certbot"
certbot certonly --nginx -d panel.example.com
```

Reload Nginx after installing the certificate, and set up automatic renewal
(`certbot renew` runs on a timer by default).

## Caddy

Caddy obtains and renews certificates for you — point a Caddyfile at the panel
and it just works:

```text title="Caddyfile"
panel.example.com {
    reverse_proxy 127.0.0.1:2053 {
        header_up X-Real-IP {remote_host}
    }
}
```

## Tips

- Keep the panel's **web base path** even behind a proxy; defense in depth.
- If you terminate TLS at the proxy, you may want `XUI_SKIP_HSTS=true` on the
  panel — see the [environment variables reference](/docs/reference/env-vars).
- Proxy the [subscription](/docs/config/subscription) server too, so its contents
  are served over HTTPS.
